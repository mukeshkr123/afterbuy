Using the provided AfterBuy MVP Scope and PRD as the single source of truth, design a complete, high-fidelity, clickable mobile app prototype covering every MVP feature, screen, state, and user flow.

Requirements:

* Create all screens required for onboarding, authentication, home, purchases/orders, product details, delivery tracking, returns, refunds, warranties, reminders, notifications, search, profile, settings, permissions, support, empty states, loading states, success states, validation errors, offline states, and edge cases mentioned in the PRD.
* Map the complete end-to-end user journey and ensure every screen is connected through realistic interactions.
* Use a modern, premium, calm, and trustworthy visual style with clean typography, subtle depth, smooth rounded corners, balanced spacing, clear hierarchy, polished icons, and restrained animations.
* Prioritize simplicity, one-handed mobile usage, accessibility, fast task completion, and minimal cognitive load.
* Follow iOS and Android mobile UX best practices while maintaining one consistent AfterBuy design system.
* Use reusable components, consistent navigation patterns, semantic colors, accessible contrast, large touch targets, and clear feedback for every user action.
* Include realistic content and sample data instead of placeholder text.
* Design light mode first and ensure the system can support dark mode.
* Add smooth micro-interactions, transitions, skeleton loaders, confirmations, undo actions, and contextual guidance where useful.
* Avoid clutter, excessive gradients, unnecessary cards, confusing navigation, and decorative elements that do not improve usability.
* Create a small design system covering colors, typography, spacing, buttons, inputs, cards, badges, tabs, bottom navigation, sheets, dialogs, alerts, lists, and status indicators.
* Clearly label each screen and organize the prototype by user flow.
* Do not add features outside the approved MVP scope.
* When the PRD is ambiguous, choose the simplest and most user-friendly MVP solution and document the assumption.

The final result should feel production-ready, premium, intuitive, cohesive, and suitable for usability testing, stakeholder approval, and developer handoff.
